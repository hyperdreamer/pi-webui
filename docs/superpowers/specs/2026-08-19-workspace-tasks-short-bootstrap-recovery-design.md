Use an exact short file-backed bootstrap to obtain fresh F-1/F-2 audit and browser evidence, then implement and independently review F-3 before final Frontier review of the complete Workspace Tasks range.

## Bootstrap Rule

The successor plan explicitly authorizes a short persisted bootstrap for each child. The bootstrap itself is the dispatch intent and must be compared byte-for-byte with the child’s first user message before `dispatch-started` is recorded. The child then reads the complete task brief at the named path and writes exactly one report at the named path. No report is admitted if the bootstrap receipt differs.
