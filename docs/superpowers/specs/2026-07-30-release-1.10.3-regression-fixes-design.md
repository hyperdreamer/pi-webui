# Release 1.10.3 Regression Fixes Design

**Date:** 2026-07-30

## Goal

Make the pending Memory workspace badge and Sessions-sidebar search release safe to publish by correcting three user-visible regressions and restoring the legacy project-memory route's independent-read behavior.

## Scope

This design covers exactly four fixes:

1. Preserve the current Memory workspace state when the user reselects the exact same workspace.
2. Make active session search a read-only expanded view that cannot mutate stored family-fold state.
3. Build one unified search source so a matching archived child retains an available current parent as context.
4. Restore the legacy project-memory endpoint's ability to read project memory independently of global-memory reads.

The work remains a patch release. It does not add routes, configuration, persistent UI state, URL state, session-daemon behavior, or a new runtime owner.

## Accepted behavior

### Exact workspace reselect

`WorkspaceController.selectWorkspace()` continues to reload the selected workspace's session data. When the selected project ID, workspace ID, and workspace path already match the requested workspace, it retains the existing `AppState.memory` value instead of replacing it with the `loading` state from `resetWorkspaceScopedState()`.

A changed project, workspace ID, or workspace path continues to reset Memory state and starts the normal scope-specific polling flow. This prevents stale cross-workspace data while eliminating the avoidable loading badge during a same-workspace reselect.

### Session search

A non-empty query builds an unfolded, availability-filtered session tree containing both current and archived sessions before it is filtered. The shared search filter receives that one complete row set, so a matching archived descendant can retain a current ancestor. The result is partitioned only after ancestor retention, preserving the sidebar's existing current and Archived areas while ensuring that an available parent is never mislabeled as unavailable. In the sidebar’s active-search partition, the Current section owns every retained non-archived row and every retained ancestor needed to render those rows as complete root-to-descendant families. Therefore an archived ancestor of a current result appears with that Current family; other archived rows remain in Archived. This prevents a depth-positive current row from being orphaned or dropped during section grouping.

While a query is active, family disclosure controls are omitted in both `SessionList` and `SessionBrowserDialog`. Results are already unfolded, so the controls have no useful immediate effect; omitting them prevents accidental writes to `expandedSessionPaths`. Clearing the query restores the unchanged user-selected fold and archive-expanded state.

### Legacy project-memory endpoint

The concrete `PiHermesMemoryProvider` gains a project-only entry read that probes and reads only the requested project's memory path. `MemoryService.projectEntries()` delegates to that operation. A missing, unsafe, inaccessible, or unreadable project memory source yields the legacy empty result; it neither probes nor reads global memory files.

The provider's existing combined `read()` contract remains unchanged. The snapshot endpoint retains its global-memory error behavior and is not made more permissive by this compatibility fix.

## Architecture

### Workspace selection boundary

`src/client/src/controllers/workspaceController.ts` remains the owner of selection-state resets. A small scope comparison at that boundary decides whether the reset patch should include the prior Memory state. No polling lifecycle logic moves into the workspace controller.

### Shared search projection boundary

`src/client/src/sessionTreeRows.ts` owns tree projection rules. It will expose a pure search projection that applies the established workspace-availability rules without archive removal or fold suppression. `SessionList` and `SessionBrowserDialog` both consume it only for active search, then pass its rows to the existing pure `filterSessionRows()` helper.

This keeps session visibility, ancestry, and `hasMissingParent` calculations in one place rather than reconstructing trees in component rendering code.

### Memory provider boundary

`src/server/memory/piHermesMemoryProvider.ts` owns filesystem and availability decisions. Its project-only read is intentionally a concrete-provider method rather than an expansion of the generic `MemoryProvider` interface: the aggregate catalog/snapshot contract needs both scopes, while only the legacy compatibility facade needs one scope independently.

`src/server/memory/memoryService.ts` remains a thin compatibility facade over the provider.

## Tests and verification

Add focused regression coverage before production changes:

- `src/client/src/controllers/workspaceController.test.ts`: exact workspace reselect preserves loaded Memory state while session loading still begins.
- `src/client/src/components/SessionList.test.ts`: active search has no mutating family disclosure control; an archived matching child retains a current parent without the `parent unavailable` badge; clearing the query preserves the prior fold state.
- `src/client/src/components/SessionBrowserDialog.test.ts`: active search likewise has no mutating disclosure control and retains ancestor context.
- `src/client/src/sessionTreeRows.test.ts` or the existing closest tree-row test file: the search projection includes current and archived related rows while respecting known workspace boundaries.
- `src/server/memory/piHermesMemoryProvider.test.ts` and/or `src/server/memory/memoryService.test.ts`: project-only reads return project entries when global file access would fail and preserve empty-result handling for unavailable project memory.

Use the repository's TDD cycle for each behavior: add one failing regression test, run it to confirm the expected failure, implement the narrow production change, then rerun the focused test. Follow with typecheck, lint for changed files, `npm run verify`, `npm run build`, and `npm run pack:dry`.

## Release notes

The existing pending Changesets continue to describe the unshipped Memory badge and sidebar search features. Add one patch Changeset for the restored legacy project-memory behavior so package consumers can identify that compatibility correction in the generated release notes.

## Non-goals

- No search persistence, history, URL query state, server-side session search, or navigation redesign.
- No change to archive lifecycle, bulk-action policy, cleanup behavior, session API contracts, or session-daemon protocol.
- No change to aggregate memory snapshot error semantics.
- No README or user-facing documentation expansion beyond Changeset-generated release notes.
