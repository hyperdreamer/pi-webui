# Passive Update Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce passive npm-release detection latency by making the existing release lookup cache expire after 15 minutes while retaining the browser’s existing 15-minute status refresh.

**Architecture:** `PiWebUiApp` already asks the selected machine for PI WEBUI status every 15 minutes. The web/API process’s `createPiWebUiReleaseLookupCache()` remains the only release-lookup cache and remains demand-driven: its first caller after expiry queries npm, and concurrent callers share the pending lookup. Change only that cache’s default TTL from six hours to 15 minutes; do not add a timer, alter the outer 60-second status cache, or change the Updates UI.

**Tech Stack:** TypeScript, Vitest, npm, Changesets.

## Global Constraints

- Preserve `PI_WEBUI_STATUS_REFRESH_MS = 15 * 60 * 1000` in `src/client/src/components/PiWebUiApp.ts`; it already provides the approved browser polling cadence and must not be changed.
- Change only the default npm release-lookup TTL from `6 * 60 * 60 * 1000` to `15 * 60 * 1000`.
- Preserve the cache’s public API, forced-refresh behavior, pending-request coalescing, error behavior, and current-version argument behavior.
- Preserve the independent 60-second `PiWebUiStatusCache` and its stale-while-revalidate behavior; accepted visible detection remains approximately 15–30 minutes rather than a strict 15-minute guarantee.
- Do not add configuration, persistent state, a background server timer, update-panel behavior, badges, buttons, plugin API changes, or user-facing documentation.
- This is web/API-side code only. Do not change `src/server/sessiond.ts`, session-runtime ownership, or the session-daemon protocol; no manual session-daemon restart is required.
- Follow TDD: make the focused default-TTL test fail first, implement the one-line behavior change, then rerun focused and full verification.
- Add one patch Changeset; do not edit `CHANGELOG.md` manually.

- [ ] **Step 2: Add a failing test for the default 15-minute expiry boundary.**

Add this test to `src/server/piWebUiReleaseLookupCache.test.ts` after the existing fresh-cache test. It deliberately omits `ttlMs`, so it exercises the production default rather than the test-only override.

```ts
it("refreshes the default release lookup at the fifteen-minute expiry boundary", async () => {
  const firstCheckedAtMs = 1_000;
  let now = firstCheckedAtMs;
  const load = vi.fn()
    .mockResolvedValueOnce("1.0.0")
    .mockResolvedValueOnce("1.1.0");
  const cache = createPiWebUiReleaseLookupCache(load, { now: () => now });

  await expect(cache.get("0.9.0")).resolves.toMatchObject({
    latestVersion: "1.0.0",
    checkedAtMs: firstCheckedAtMs,
  });

  now = firstCheckedAtMs + (15 * 60 * 1000) - 1;
  await expect(cache.get("0.9.0")).resolves.toMatchObject({
    latestVersion: "1.0.0",
    checkedAtMs: firstCheckedAtMs,
  });
  expect(load).toHaveBeenCalledOnce();

  now += 1;
  await expect(cache.get("0.9.0")).resolves.toMatchObject({
    latestVersion: "1.1.0",
    checkedAtMs: now,
  });
  expect(load).toHaveBeenCalledTimes(2);
});
```
