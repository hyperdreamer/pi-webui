# Release 1.10.3 Regression Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the four approved regressions, prove each with focused tests, and leave a verified patch-release candidate ready for the GitHub Actions publication workflow.

**Architecture:** Keep workspace-reset ownership in `WorkspaceController`, add a pure all-status session-search projection in `sessionTreeRows.ts`, and let both session views consume that projection only for active searches. **Tech Stack:** TypeScript 6, Lit 3 custom elements, Vitest 4, Fastify 5, npm 11, Changesets.

## Global Constraints

- Preserve the existing session-daemon ownership, protocol, routes, browser URL behavior, and application-relative client URL conventions.
- Do not add dependencies, configuration, persistent search state, server-side session search, or new API routes.
- Do not alter `MemoryProvider.read()` or aggregate snapshot error semantics.
- Use a red–green TDD cycle for every production behavior change: add one regression test, run it and observe its expected failure, implement only the necessary code, and rerun the focused test.
- Keep active search locally owned and read-only with respect to `expandedSessionPaths` and `archivedExpanded`.
- Add a patch Changeset for the legacy project-memory correction; do not hand-edit `CHANGELOG.md`.
- Run focused checks before broad checks. Before release preparation, run `npm run verify`, `npm run build`, `npm run pack:dry`, and `git diff --check`.
